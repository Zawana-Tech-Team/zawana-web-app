# Private course management

The Admin private-course page has two views: Course catalog and Booking requests. Course cards emphasize the course name, image, description, duration, price, assigned coaches and availability. New course sits in the page header beside the existing private-booking entry point. Repeated headings, totals and placeholder descriptions are removed.

Create and Edit share a responsive dialog with a fixed action footer, visible description/image, a prominent price field and selectable coach tiles. Existing category, duration, price, status and coach-assignment validation remain in place. Required fields, upload/submission guards, inline errors and a retained draft support recovery. Removal uses a confirmation dialog and the existing endpoint: courses with booking history are archived; unused courses may be deleted.

Saving an unchanged image now preserves its URL rather than sending that URL to the base64 upload endpoint. Removing an image saves `null`; new images use the existing course-image upload API. If course details save but image upload fails, the dialog retains the saved course ID and explains that retrying saves the image against the same course. The catalog refreshes to reflect the partial save. Duplicate submissions are guarded synchronously.

Booking requests use one responsive list instead of separate desktop tables and mobile cards. Each row displays the course/member/coach, session date and time, court, booking price, payment status and booking status. Contact information, reference, requested timestamp and any payment deadline move into a details dialog. Dates and timestamps use Yangon time. Search, booking status, coach and date-range filters remain available with ten requests per page, reset controls, loading feedback and retry actions. Background updates reuse the shared booking subscription without replacing loaded rows with a spinner.

The details dialog refreshes from the server, supports retry and links to the existing booking-history route filtered to that booking. This is an oversight view; it introduces no booking-edit, approval, payment, refund or rescheduling mutations. Existing booking snapshots and business rules remain authoritative. No API or schema changes are required.

Validation: `npm run build`, `npm run lint:stabilization`, and `node scripts/test-private-course-management-browser.mjs`. The isolated browser journey uses the real API and a temporary database to cover course create/edit/status/removal, validation, image upload/preservation/removal, failed upload retry, duplicate submissions, booking snapshot preservation, requests search/status/coach/date filters, pagination, details retry, live status updates and booking-history navigation. It captures catalog/editor/request/detail layouts at 1440, 768, 390 and 320 pixels and is included in CI and the stabilization browser runner.
