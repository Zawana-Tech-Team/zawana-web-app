# Finance, content and achievements

Admin Finance now uses a single responsive transaction list with one server pagination control. It highlights the customer/service, transaction date, business, original payment method, final amount and status. Search, business/status filters remain prominent; date range, method and sorting sit under More filters. Loading, retry, refresh and empty states distinguish unavailable data from an empty ledger. Background payment updates retain the loaded list.

The summary emphasizes the filtered net total alongside gross, discounts and refunds. It displays the existing server aggregates across every matching record, including all matching statuses, and does not redefine revenue or recalculate money from the current page. Transaction details retain subtotal/discount/tax where relevant, date and recorded time in Yangon, staff, original payment method, confirmation mode and audit references. Same-day recorded times appear on list rows; historical transaction dates stay accurate. Refunds retain their signed amounts.

Refund requests remain available below the ledger in a disclosure with the existing processing workflow. RefundInbox accepts optional embedded/empty presentation props to avoid a repeated heading and explain an empty inbox. Other callers retain their existing presentation by default. Owner Finance shares the read-only ledger interface and does not expose the admin refund-request section.

Content & achievements has image-led cards, one publication status per item, search, type/status filters and a visible nine-story pager over the existing loaded catalog. Repeated destination/visibility descriptions and instructional introductions are removed. Edit, publish now, public article links and confirmed deletion remain available.

The shared create/edit dialog keeps title, category, summary, article, cover image and publication controls, with a fixed Cancel/Save footer. Optional image URLs and registration/information links use a disclosure. Native select controls in the scrolling editor avoid a popup closing during scroll; page filters retain the shared select component. Draft, live and future scheduled publication rules remain unchanged. Submission/upload guards prevent accidental closing and duplicate saves; inline errors retain the draft.

Content mutations use the existing APIs and update the local catalog from the successful response. Saving a story does not depend on refreshing unrelated operation data, so a later refresh failure cannot encourage a duplicate create. No database schema, financial calculation, transaction mutation, publication authorization or public-page rules change.

Validation includes the production frontend build, stabilization/rescheduling lint, the existing content browser journey, the existing separated badminton finance browser journey and the new isolated admin finance/content browser journey. The latter verifies totals across pages, filters/sorting, receipt/audit details, negative refunds, immutable ledger and booking snapshots, content create/edit/failure recovery, duplicate submissions, scheduling/publication/public visibility, unpublishing/deletion, community posts and 1440/768/390/320px layouts. It is included in CI and the stabilization browser runner.
